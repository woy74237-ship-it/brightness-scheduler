# 輝度スケジューラ

ディスプレイの輝度（明るさ）を時間指定で自動調整する、Windows 用のタスクトレイ常駐アプリです（[壁紙スケジューラ](https://github.com/woy74237-ship-it/wallpaper-scheduler) の明るさ版）。

## ダウンロード

**[最新版をダウンロード（GitHub Releases）](https://github.com/woy74237-ship-it/brightness-scheduler/releases/latest)**

`BrightnessScheduler-v〇.〇.〇.zip` を展開して `BrightnessScheduler.exe` を起動するだけで使えます（インストール不要・Windows 10 / 11 対応）。
初回起動時に「Windows によって PC が保護されました」と表示された場合は、「詳細情報」→「実行」で起動できます。

新しいバージョンに更新するときは、アプリを終了して今の exe を上書きしてください（設定と自動起動はそのまま引き継がれます）。
別のフォルダに展開した場合は、自動起動が古い exe を指したままになるので、新しい exe の設定画面で「Windows の起動時に開始」を一度オフ→オンにしてください。

## 使い方

1. `BrightnessScheduler.exe` を起動（初回は設定画面が開きます）
2. 「追加」で時刻・明るさ（0〜100%）・変化の仕方を登録

変更はその場で保存・反映されます。

- **その時刻に切り替え**: 時刻になったら、その明るさにすぐ変えます。
- **なめらかに変化**: 前の時刻からゆっくり変え始め、ゆっくり止まるように変えて、その時刻にちょうどその明るさにします（例: 18:00 に 60%、22:00 に 30%（なめらか）なら、20:00 には 45%）。
- 明るさはつながっているすべてのモニターに同じ値で設定します（各モニターの最大値に対する割合）。
  同じ値でも見え方が違うときは、「モニターごとの補正」で調整できます（下記）。
- 画面上部のグラフで、24 時間の明るさの変化を確認できます。
- モニター本体のボタンで明るさを変えた場合は、「今すぐ適用」でスケジュールの明るさに戻せます。
- 目が疲れたときなどは、「**一時的に暗くする**」（設定画面の上部、またはタスクトレイのメニュー）で、
  スケジュールに関係なく今の明るさを暗くできます。30 分・1 時間・2 時間・元に戻すまで、から選べ、
  時間が来たら自動でスケジュールの明るさに戻ります。暗さは「少し（3/4）」「半分」「かなり（1/4）」から選べます。
  時間と暗さの**どちらか一方を選ぶだけで、すぐ暗くなります**（もう一方は前回選んだもの・今の設定を使います）。
  明るさ 0% でもまぶしいときは「**さらに暗く（0% ＋フィルター）**」を選ぶと、明るさを 0% にしたうえで、
  すべての画面に半透明の黒いフィルターを重ねます（HDR のモニターにも効きます。クリックは下の画面に素通りし、
  スクリーンショットや画面共有には写りません）。フィルターの濃さ（10〜90%）は、同じメニューの
  「フィルターの濃さを調整…」で、実際の画面を見ながらスライダーで決められます。
- スリープからの復帰・ロック解除・モニターの接続時には、少し待ってから設定し直します。

### モニターごとの補正

設定画面の右下「モニターごとの補正」で、モニターごとに実際に設定する値を調整できます。
方式はモニターごとに選べます。

| 方式 | 内容 | 例 |
| --- | --- | --- |
| 範囲で指定 | 0% のとき・100% のときの値を決め、その間を比例させる | 10〜70% なら、50% → 40% |
| ずらす | どの明るさでも同じだけ足す・引く | −15% なら、50% → 35% |
| 倍率 | 掛ける | 70% なら、50% → 35% |

「確認用の明るさ」を動かすと、補正した明るさを実際の画面で見比べられます（保存するまでスケジュールには反映されません）。

「範囲で指定」は、各モニターの「**ガイドで合わせる**」を押すと、手順に沿って合わせられます。

1. 確認用の明るさが 0% になるので、もう 1 台と同じ暗さに見えるまで「0% のとき」を動かす
2. 確認用の明るさが 100% になるので、同じ明るさに見えるまで「100% のとき」を動かす
3. その間の明るさは自動で比例して合う
補正はモニターの接続端子ごとに保存され、つないでいないモニターの補正も残ります。

### 対応しているモニター

- **外付けモニター**: DDC/CI に対応したもの。モニターの設定（OSD メニュー）で DDC/CI がオフになっていると変更できません。
- **ノート PC の内蔵画面**: Windows の明るさ設定（WMI）で変更します。
- **HDR がオンのモニター**: 下の「HDR のモニターについて」を参照してください。

### HDR のモニターについて

HDR がオンのあいだは、多くのモニターで本体の明るさを変えても表示に反映されません。
そのため、HDR がオンのモニターでは、Windows の
「設定 > ディスプレイ > HDR > **SDR コンテンツの明るさ**」を変えます。

- 0〜100% は、Windows の設定のスライダーと同じ値です（80〜480 nits）。
  0% にしても、HDR がオフのモニターほどは暗くなりません。
- 変わるのはデスクトップやふつうのアプリ（SDR の表示）の明るさです。HDR の動画やゲームの明るさは変わりません。
- **Windows の設定そのものを書き換えます。** アプリを終了したり削除したりしても、最後に設定した値のままになります。
  元に戻したいときは、Windows の設定画面で調整してください。
- この書き換えには、Microsoft が公開していない Windows の機能（Windows の設定画面が使っているもの）を使っています。
  Windows の更新で動かなくなった場合は、HDR のモニターだけ明るさが変わらなくなり、通知でお知らせします。
- Windows の設定を変えられたくない場合は、設定画面の「**HDR のモニターも変える**」をオフにしてください。
  HDR がオンのモニターには何もしなくなります（HDR をオフにしたモニターは、これまでどおり変えます）。

## ビルド

追加のインストールは不要です（Windows 標準の .NET Framework 4.x の `csc.exe` を使用）。

```powershell
.\build.ps1
```

`bin\BrightnessScheduler.exe` が生成されます。

## 配布用 ZIP の作成

```powershell
.\package.ps1
```

`dist\BrightnessScheduler-v<バージョン>.zip`（exe と利用者向けの `assets\README.txt`）と、
改ざん確認用の `.zip.sha256` が生成されます。
作成した ZIP は Microsoft Defender で自動的にスキャンし、検出された場合は ZIP を削除して中止します
（スキャン単体でも `.\tools\scan-file.ps1 <ファイル>` で実行できます）。

リリースの手順:

1. `src/Core.cs` 先頭のバージョン（3 か所）を上げる
2. `.\package.ps1` を実行（Defender のスキャンで検出されたら公開しない）
3. コミットしてタグを付け、GitHub に push する（例: `git tag v1.0.1`）
4. **プレリリースとして** Release を作る（`gh release create ... --prerelease`。最新版にはならない）
5. **自分の PC で実際に試す**（Release のページから ZIP をダウンロード → 展開 → 起動）
6. 問題がなければ、最新版に切り替える（`gh release edit <タグ> --prerelease=false --latest`）

> ローカルのスキャンは「既に判定済みのファイル」しか検出できないことがあります。
> 新しく作ったファイルは、ダウンロードや実行のときに初めてクラウドで判定されるため、
> 手順 5 の「実際にダウンロードして試す」を省略しないこと。

アイコンのデザインを変えたときは `tools/MakeIcon.cs` を編集し、`.\tools\make-icon.ps1` で `assets/app.ico` を再生成します。

## 紹介ページ・記事

紹介ページは `site/` にあり、main ブランチに push すると GitHub Actions（`.github/workflows/pages.yml`）で
GitHub Pages に公開されます。記事の原稿は `docs/note.md`（note 用）と `docs/zenn.md`（Zenn 用）です。

画像は次のスクリプトで作ります（`promo/` と `docs/images/` は手元だけの素材で、Git には含めません）。

1. `.\tools\make-screenshots.ps1` … アプリのスクリーンショット（サンプルのスケジュールと架空のモニター名で撮影。明るさは変えない）を `docs/images/` に
2. `.\tools\make-promo.ps1` … シェア用画像（OGP）・note の見出し画像・背景を `promo/` に
3. `.\tools\make-site-assets.ps1` … 1・2 とアイコンから、紹介ページ用の画像を `site/images/` に

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `src/Core.cs` | バージョン・設定の保存・スケジュール計算・自動起動 |
| `src/Display.cs` | モニターの明るさの読み書き（DDC/CI・WMI）と専用スレッド |
| `src/Hdr.cs` | HDR がオンの画面の「SDR コンテンツの明るさ」の読み書き |
| `src/App.cs` | タスクトレイ常駐部とエントリポイント |
| `src/MainForm.cs` | メイン画面 |
| `src/EntryDialog.cs` | 追加・編集ダイアログ |
| `src/CorrectionDialog.cs` | モニターごとの補正の画面 |
| `src/BrightnessControls.cs` | グラフ・カード・スライダーなど |
| `src/Controls.cs` / `Dialogs.cs` / `Theme.cs` | 壁紙スケジューラと共通の部品・配色 |

設定は `%APPDATA%\BrightnessScheduler\settings.json` に保存されます。
